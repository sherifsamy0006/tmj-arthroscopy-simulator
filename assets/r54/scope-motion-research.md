# Scope motion: r53 defects and an r54 implementation basis

**Takeaway:** the next movement change should preserve physical input order and a consistent external hand frame. r53 currently produces different shaft motion from the same combined gesture depending on event batching, rotates the supposed external hand frame with the scope image, and discards permissible movement together with blocked steering. Increasing sensitivity or starting shallower cannot repair these defects. Passing software checks establishes implementation properties, not clinical realism.

Research date: 2026-10-25. Read-only production review; diagnostic files only were created here. No publishing, author contact, or production source changes.

## Evidence and what it does—and does not—support

Existing local sources reviewed first: `references/r32-public-evidence/portal-motion-evidence.json`, `references/r33-portals/portal-access-quantitative-evidence.json`, `references/r33-cannula/evidence.json`, and the stored arthroscopy technique texts. Agent Reach search routing was read; its mcporter/Exa executable was unavailable, so primary-source web search/read was used. No restricted course lessons were accessed.

- **TMJ manipulation:** Atteya's author-written [Operative Arthroscopy of the TMJ](https://intech-files.s3.amazonaws.com/a043Y000010Jz7vQAC/a093Y00001d3INbQAM/Final-Operative%20arthroscopy%20of%20the%20TMJ%20%282024-05-22%2008%3A44%3A27%29.pdf), p.26, describes exploration using anteroposterior/mediolateral manipulation and rotation of a 30-degree lens after scope insertion into the cannula. This supports distinct, combinable manipulation and optical rotation. It does not establish a universal pivot coordinate, shaft range, joint depth, or a calibrated force law. Do not transfer the chapter's example dimensions into this model.
- **A portal is a tract, not a proven universal capsule point:** the primary [Krause et al. 2019 technical note](https://pmc.ncbi.nlm.nih.gov/articles/PMC6444874/) uses patient imaging plus facial surface geometry and channels selected for anatomy, pathology and instrument dimensions. Its discussion recognizes mandibular manipulation as an access variable. Consequently, the current fixed capsule-crossing point is an explicitly selected computational pivot. This source does not prove that its effective physical fulcrum is exactly at skin, exactly at capsule, or fixed during the procedure. Moving it to an arbitrary skin point would replace one unsupported assumption with another.
- **Device geometry:** the [Nexus manufacturer page](https://www.nexuscmf.com/products/) lists scope 501200 as 1.9 mm diameter, 63.1 mm working length, 30-degree direction of view and 65-degree field of view. It lists a separate collar-lock cannula. These data support the oblique optic and separate scope/sheath identities, not the actual hand-grip location, cannula outside diameter, lens protrusion, camera coupler clocking or tissue constraint. The current `TOOL.length` is not a measured hand-to-pivot distance.
- **Separate scope and camera-head rotation:** the primary [Palliyali et al. mixed-reality scope study](https://link.springer.com/article/10.1007/s10055-025-01278-y) explicitly models relative telescope and camera-head rotation: scope rotation redirects the angled viewing axis, while camera-head rotation changes displayed orientation. This is a useful rigid-optics principle, but the experiment is hysteroscopy, not Nexus TMJ hardware. It cannot calibrate this assembly. The r53 fixed-coupler assumption can remain one explicit mode; automatic superior-up stabilization is a teaching aid, not a substitute for the operator's camera-head control.
- **Validation distinction:** the primary [arthroscopic FAST simulator study](https://pmc.ncbi.nlm.nih.gov/articles/PMC8923590/) separates image centering, horizon control, telescoping and periscoping tasks. Its measured performance and construct-validity results concern that tested platform. They support testing these skills separately, not declaring this simulator realistic because analogous automated tests pass.

No retrieved primary source provided a same-specimen registered skin/capsule tract, measured effective fulcrum, time-stamped expert TMJ scope poses, contact forces, or camera/scope relative rotation for the selected device. These remain missing measurements.

## Reproduced r53 defects

Diagnostic: `diagnose-r53-input.mjs` imports the real `dist/controls-r53.mjs` and `dist/navigation-r53.mjs`. Results are saved in `r53-input-diagnosis.json`. Values below are software/model measurements, not clinical measurements.

| Defect | Source | Reproduction and effect |
|---|---|---|
| Combined motion depends on batching | `instrumentInput.take()` | It applies all steering using the old roll/depth, then adds depth/roll. `{x:10,y:4,roll:90,depth:1}` delivered once versus 100 equal chunks differs by **6.36276 degrees** in shaft axis and **0.24546 mm** at the tip. Collision-worker timing therefore changes the requested physical path. |
| Summing loses noncommutative order | `instrumentInput.add()` | Roll-then-steer versus steer-then-roll differs by **11.29273 degrees** for the test sequence, yet both sequences have the same accumulated components. A continuous sweep of the resulting endpoint chord cannot recover the lost ordered path. |
| External handle frame rotates with the image | `handlePose()` | Same horizontal handle command at telescope rolls 0/180 gives shaft response vectors differing by **179.19568 degrees**, because it uses `imageBasis().right/up`. This is a coherent image-relative interface but contradicts the claim that it represents one fixed external direction of hand motion. Preserve a separate direct-view teaching mode if desired. |
| Contact discards unrelated freedom | `discardBlocked()` | After an attempted combined movement, queued x=2, depth=-0.2 and roll=5 are all cleared solely because their signs match the previous request. The method does not know which component was obstructed. Valid withdrawal or optical roll may therefore be lost with blocked steering. |
| Wrapped roll interpolates the long arc | `drag-sweep-r50.mjs` `lerp()` | From 179 degrees to wrapped -171 degrees, a half-admitted combined move yields 4 degrees instead of the shortest-arc -176 degrees. Axisymmetric collision makes the shaft envelope insensitive to roll, but the displayed optical orientation can jump. |
| Within-frame turns can disappear | `gestures-r53.mjs` `flush()` | Only the latest pointer locations are retained per frame. Intermediate turning/reversal paths are not preserved; coupled centroid/pinch/twist channels are summed later. The effect must be tested with timestamped input replay, not only a single long drag. |

Positive invariants already present: the diagnostic returns **30 degrees** between shaft and viewing axis, and **1 mm** tip displacement for 1 mm pure axial insertion. Preserve these properties. A single rigid shaft and genuine fulcrum inversion are useful foundations; they are not the whole handling model.

## Concrete implementation proposal

1. **Separate the physical state from UI coordinates.** Keep shaft orientation, insertion relative to the chosen portal, telescope axial rotation and optional camera-head rotation as explicit state. Store continuous/unwrapped angular state internally. The camera and locator must derive from this same state. Pure telescope roll redirects the 30-degree viewing cone without translating the shaft tip; pure camera-head rotation changes image orientation without changing the shaft/viewing ray. Keep fixed coupler and independent camera-head modes explicit until hardware coupling is established.
2. **Use an external hand frame in handle mode.** Choose and display a stable patient/locator-aligned horizontal and vertical basis, frozen for a drag or otherwise defined independently of optical roll. For shaft axis s, chosen grip lever L and hand increment Δh, form the proximal vector `-L*s + Δh`, then normalize its negative to recover the new shaft direction. Remove axial contribution from a lateral handle command; use a distinct insertion channel. Update L with insertion during the same integration step. L remains a model parameter until actual grip position is measured. In direct-view mode, image-relative controls may intentionally remain distinct.
3. **Integrate chronological input.** Retain timestamps and ordered simultaneous increments. Use one deterministic small integration step for steering, insertion and roll together, or midpoint evaluation of depth/roll within each step. Advance a requested physical state independently of asynchronous worker completion. Submit chronological pose segments to the existing swept collision guard; preserve corners/reversals. Coalesce only samples demonstrated equivalent within a stated geometric error, not arbitrary x/y/depth/roll totals. Use `getCoalescedEvents()` where available, with ordinary Pointer Events as fallback. Queue bounds must not silently erase curvature or produce a long delayed drift.
4. **Reconcile requested/admitted states at contact.** Stop the offending requested segment at its proven prefix. Rebase subsequent hand deltas to the admitted pose so reversal responds immediately. Preserve independent roll and withdrawal only after separately checking the residual path; do not assume all combinations of individually clear degrees of freedom are safe. For axisymmetric scope roll, its collision envelope is unchanged, but this exception must not later apply to a non-axisymmetric cannula/handle without testing. Use shortest-arc or continuous-angle interpolation everywhere, including partial acceptance and visual following.
5. **Do not invent physical freedom to match a desired range.** Keep the current hard-source geometry and collision tolerance while fixing the interface defects. A flexible portal, translating fulcrum, cannula bending, skin friction and capsule compliance require additional data/modeling. If an exploratory pivot adjustment is offered, label it model registration and show its location; never hide it behind sensitivity. Real pistoning is axial motion of the assembled scope/cannula under the chosen model, not arbitrary world-space free camera translation.
6. **Treat contact quality separately from kinematics.** Present the actual point/part that stopped the modeled assembly and distinguish a soft reconstructed lining boundary from original hard-source contact. Software collision is not tactile resistance. The current bare 1.9 mm shaft and approximate proximal body do not prove the swept occupied volume of the complete cannula assembly. Do not enlarge limits or claim realistic tissue feel without that geometry and force evidence.

## Quantitative nonclinical validation

These are proposed engineering checks, not clinical acceptance criteria. Fix tolerances before observing a candidate's result.

- **Replay invariance:** one timestamped curved combined gesture replayed through 30/60/120 Hz render schedules, varied worker delays and native event coalescing. Compare the entire admitted trajectory, not just the endpoint. Suggested numerical targets: <0.1 degree shaft/optic difference and <0.01 mm tip difference for identical traces; report max and RMS errors. Any tolerances must be supported by the chosen integrator resolution.
- **External frame invariance:** apply identical external hand vectors at telescope roll 0/90/180/270. Shaft response should be identical within numerical tolerance; the image may rotate differently. This test deliberately differs from direct-view mode.
- **Synthetic fulcrum bench:** with known pivot F, shaft s, distal length l and external lever L, verify tip `F+l*s`, hand `F-L*s`, opposite transverse response, and the small-motion ratio `|Δtip|/|Δhand|≈l/L`. Test two insertion depths. These dimensions are synthetic fixture values, not TMJ measurements.
- **Optic bench:** verify fixed 30-degree DOV, 65-degree FOV, no tip translation during axial scope roll, a full 360-degree conical viewing sweep, camera-head rotation that does not redirect the ray, and continuity across ±180 degrees.
- **Contact replay:** oblique steering-plus-roll-plus-withdrawal toward a synthetic hard obstacle; prove no tunneling, correct chronological prefix, immediate reversal, preserved separately admissible residual channels and no stored drift after release/cancel. Test tiny reversals, pointer loss, mode switches, two-finger join/leave and irregular frame timing.
- **Performance:** record event-to-request, worker processing and event-to-render latency distributions, plus queue age, rather than equating a higher FPS counter with correct handling. If contact computation cannot keep pace, improve the computation/queue before adding smoothing or inertia.
- **Human validation still needed:** compare the implemented hand-frame/roll coupling against a real assembled scope/camera using a simple calibration target and recorded hand/tip movements; then have experienced TMJ arthroscopists assess the specific movement tasks. Do not infer face validity from larger movement, attractive tissue, or source-hash checks.

## Measurements still needed

Same-subject skin and capsule registration; actual portal tract and its compliance; camera coupler/keying and independent head rotation; grip location; cannula OD/ID and tip seating; lens protrusion and optical center; complete occupied assembly shape; expert scope/camera trajectories with jaw pose; force-displacement and friction at the tract/lining; realistic manipulation latency for a tracked input device. Existing manufacturer dimensions and anatomical population averages do not supply these values.
